# Payment operations

Pending guest requests have no checkout. Approve the current booking version only after all inventory and resource requirements pass. The stored common policy determines full payment, deposit or arrival collection. The guest uses the hosted Paymob methods actually enabled for the designated merchant.

The browser return page is informational. Confirm payment from signed transaction events or authenticated inquiry. Check merchant/account, environment, integration, currency, amount and original transaction identity. Distinct provider updates remain recorded; duplicated financial effects are rejected.

For an unknown checkout result, use the existing attempt's reconciliation action. Do not create another charge because a browser timed out. Late money after expiry/cancellation creates an exception; it does not reallocate the booking. Decide with the guest whether to refund or offer a separately accepted new booking.

Record offline money only after independently verifying cash or bank receipt. Select the booking, method, amount, currency and real receipt reference. An operational receipt is not represented as a tax invoice.

Refund flow: select an original online transaction or offline receipt, request an amount and explain the manual review of the accepted cancellation policy. The server attaches the actual policy and receipt evidence and enforces the remaining cap. A permitted approver reviews the saved request. Online execution requires the configured merchant refund capability and current approval/version; an uncertain outcome remains unknown for reconciliation. Offline completion records money already returned. Never treat the approval alone as proof of refund payment.

Finance reports separate gross receipts, refunds, chargebacks/reversals, net cash, receivables and customer liability by currency. Period cash uses effective timestamps in Africa/Cairo. Current booking state is used for operational balances; this is not historical revenue recognition.

Sandbox/live validation is pending the owner-designated merchant and authorized test amount. Record provider-confirmed transaction/refund IDs privately, not credentials or card data.
